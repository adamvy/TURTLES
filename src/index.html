What is running?
All the way into the guest.
The browser downloads QEMU as WebAssembly and boots the ARM image. One boot loads T0 and both language layers. The language command simply selects which parser/compiler reads your next input. Both are T0 programs. New code is parsed and compiled inside that machine. The JavaScript host option runs the same language sources in the original T0 interpreter.
Bare metal here means no operating system beneath T0 in the virtual machine. This demo does not claim a boot on physical ARM hardware.

      
Run it locally
Same bytes. Another machine.
Download the single ELF image below. Install QEMU (brew install qemu on macOS; sudo apt install qemu-system-arm on Ubuntu), then run:
qemu-system-aarch64 -machine virt-8.2 -cpu cortex-a53 -accel tcg -m 512M -smp 1 -nographic -device loader,file=turtles.elf,cpu-num=0
The image boots into T0. Enter :js or :som to select that reader; :t0 returns to T0 without clearing any state. Exit QEMU with Ctrl-a, then x. For multiline input, enter :paste, your program, and :end on its own line.

Memory, browser support and self-hosting
The guest has 512 MiB RAM and no garbage collector. Its arena and heap grow monotonically. Exhaustion halts the guest; reboot starts a fresh machine and clears its state.
The browser emulator reserves a larger shared memory address space than the guest RAM. Desktop Chrome is the primary target. A download of approximately 58 MB is required on first boot; a supported browser and enough memory are needed. GitHub Pages uses a same-origin service worker to enable WebAssembly threads.
The JS-like and SOM parser/compiler layers execute in T0. A language switch changes how the next input is read, while keeping the stack, bindings and heap. Their calling conventions and object models can differ; shared storage does not make the dialects identical. The ARM primitive core is assembly, and the image builder remains JavaScript running under Node. A guest that rebuilds its own native image is a future milestone.
Target: 64-bit ARMv8-A (AArch64), Cortex-A53, QEMU’s virt-8.2 board, 512 MiB RAM and PL011 serial console. This is a different platform from upstream’s planned RP2040 / Cortex-M0+ target.
T0 language semantics are preserved with bounded memory and repairs for malformed input and captured locals. JavaScript host objects and prototypes are not exposed by the ARM guest. The JS-like dialect has function-scoped let, functions, arrows, mutable closures and recursion; it does not implement full JavaScript, objects, classes, string literals or const.
The SOM layer supports expressions, messages, blocks and classes. It does not provide native primitive declarations, nonlocal returns from blocks or the full SOM standard library. Ordinary method ^ returns are supported.
Browser QEMU 8.2 comes from pinned, checksum-verified author-hosted Wasm artifacts. These binaries are downloaded on demand; the author did not identify their exact source commit.
